01 / THE BLIND SPOT

A clean diff is not a clean filesystem.

Agents can leave executable caches, environments, hooks, and metadata that ordinary code review never shows. AWB makes the filesystem—not Git—the unit of review.

02 / THE BOUNDARY

Kernel block. Full-tree receipt.

Two small mechanisms do one clear job. Landlock limits where the child can persist changes; content snapshots tell you exactly what changed inside.

  1. 01

    Declare

    Keep the open JSON policy beside your code. Nothing in your home or credentials is added implicitly.

    "allow_write": ["."]
  2. 02

    Run

    Put any local coding agent after --. Its terminal stays familiar; the write boundary is inherited.

    awb run -- claude
  3. 03

    Review

    Read one stable JSON receipt covering content, permissions, links, ignored files, and Git metadata.

    awb inspect .awb/…

04 / START LOCAL

A boundary in three commands.

Build from the open-source repository today. No daemon, account, telemetry, or global configuration.

Enforced: Linux 6.2+ / Landlock ABI 3+
cargo install --git https://github.com/B-Divyesh/sf-agent-write-barrier
cd your-project
awb init
awb check
awb run -- claude

HONEST BY DESIGN

A write boundary, not a magic shield.

  • ✓
    It does

    Block persistent filesystem writes outside policy on supported Linux, then hash watched trees before and after.

  • ×
    It does not

    Isolate networks, processes, devices, kernel bugs, or hostile same-user processes. Pair with a VM when needed.

  • !
    Fallback is labeled

    Unsupported platforms fail closed. Explicit audit-only mode reports evidence but never pretends to enforce.
